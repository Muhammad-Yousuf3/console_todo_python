# Todo Console Application Constitution

## Core Principles

### I. Spec-First Development

All implementation MUST be preceded by formal specification. No code is written until:
- A feature specification exists in `specs/<feature>/spec.md`
- An implementation plan exists in `specs/<feature>/plan.md`
- Testable tasks exist in `specs/<feature>/tasks.md`

Rationale: Specifications enforce clarity, prevent scope creep, and enable deterministic agent-driven development.

### II. No Manual Coding

All code MUST be generated by Claude Code. Human intervention is limited to:
- Providing requirements and clarifications
- Reviewing and approving generated artifacts
- Running commands when explicitly instructed

Manual edits to source files are prohibited. If changes are needed, they MUST be requested through the agent interface.

Rationale: Ensures reproducibility, maintains audit trail, and validates the agentic development workflow.

### III. In-Memory Only

The application MUST NOT persist data beyond the runtime session:
- No file I/O for task storage
- No database connections
- No external storage services
- All tasks exist only in memory during execution

Rationale: Simplifies Phase I scope, eliminates infrastructure dependencies, and focuses on core domain logic.

### IV. Deterministic Behavior

All operations MUST produce predictable, reproducible results:
- Same inputs yield same outputs
- No reliance on external state or randomness
- Clear error messages for all failure modes
- Explicit handling of edge cases

Rationale: Enables reliable testing, debugging, and validation of agent-generated code.

### V. Minimal Viable Implementation

Features MUST implement only what is explicitly specified:
- No speculative additions
- No premature abstractions
- No unused code paths
- YAGNI (You Aren't Gonna Need It) enforced

Rationale: Reduces complexity, accelerates delivery, and maintains focus on Phase I objectives.

### VI. Test-Driven Validation

When tests are specified, they MUST be written before implementation:
- Red-Green-Refactor cycle enforced
- Tests define acceptance criteria
- All edge cases covered by tests
- No implementation without failing tests first

Rationale: Guarantees code correctness and provides executable documentation.

## Technology Stack

- **Language**: Python 3.13+
- **Package Manager**: UV
- **Development Agent**: Claude Code
- **Methodology**: Spec-Kit Plus (Spec-Driven Development)
- **Storage**: In-memory only (Python data structures)

## Development Workflow

### Mandatory Sequence

1. **Specification** (`/sp.specify`): Define feature requirements
2. **Planning** (`/sp.plan`): Create implementation architecture
3. **Task Generation** (`/sp.tasks`): Break plan into testable tasks
4. **Implementation** (`/sp.implement`): Execute tasks via Claude Code
5. **Review**: Validate against acceptance criteria

### Repository Structure

```text
.specify/
├── memory/
│   └── constitution.md    # This file
├── templates/             # Spec-Kit Plus templates
└── scripts/               # Automation scripts

specs/
└── <feature>/
    ├── spec.md            # Feature specification
    ├── plan.md            # Implementation plan
    └── tasks.md           # Testable task list

src/                       # Application source code
tests/                     # Test files
history/
├── prompts/               # Prompt History Records
└── adr/                   # Architecture Decision Records
```

### Code Quality Standards

- Type hints MUST be used for all function signatures
- Docstrings MUST follow Google style for public APIs
- Maximum function length: 50 lines
- Maximum cyclomatic complexity: 10
- All public functions MUST have explicit return types

## Governance

### Amendment Process

1. Propose change via specification
2. Document rationale and impact
3. Obtain approval before implementation
4. Update all dependent artifacts
5. Increment constitution version

### Versioning Policy

- **MAJOR**: Breaking changes to principles or workflow
- **MINOR**: New principles or sections added
- **PATCH**: Clarifications or typo fixes

### Compliance

- All PRs MUST verify constitution compliance
- Violations MUST be documented and justified
- Complexity beyond specification requires explicit approval
